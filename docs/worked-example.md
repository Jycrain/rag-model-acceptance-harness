# Worked example (synthetic data)

Everything below is reproducible offline: the demo is a fictional library assistant, generated by `examples/demo/generate_demo.py`.
No real campaign data is published in this repository. If you publish your own aggregates, follow [anonymization.md](anonymization.md).

```bash
python examples/demo/generate_demo.py
python src/compare.py --config examples/demo/config.json
python src/build_excel.py --config examples/demo/config.json --out comparison.xlsx
python src/verify_deliverables.py --config examples/demo/config.json comparison.xlsx
```

## Setup
- 10 recurring questions × 2 profiles (`member`, `visitor`) = 20 passes per series, 3 model configurations (`model-a`, `model-b`, `model-c`).
- Citation convention of the demo: bold text starting with `DOC_<n>_` (`citation.preset = bold_prefixed`). Yours may differ: [status-rule.md](status-rule.md).

## Result (answers with at least one cited source vs without)

| Series | Ok | Ok - partial | Ko |
|---|---|---|---|
| model-a | 19 | 1 | 0 |
| model-b | 16 | 4 | 0 |
| model-c | 20 | 0 | 0 |

## What each branch of the demo shows
- **Plain partial** (model-a, one pass): the answer exists, cites nothing. Orange, not red.
- **Announcement** (model-b): "I am consulting the knowledge base…". Complete by the rule, empty for a human: ranked partial, flagged by a blind audit, kept with an explicit note instead of a rule exception.
- **Unmarked link** (model-b, visitor, question 09): a bare URL raises a *conflict* from the broad detector. The comparison blocks until the owner decides; the decision (`validated_conflicts.json`) is bound to the SHA-256 of that very answer, and the rule is not touched.
- **Retry after a technical failure** (model-c): both attempts are journaled, the last `ok` line is the pass used, `replays` counts it.

## Reading it correctly
- The status measures the presence of a cited source, not relevance. A cited but unrelated source is Ok.
- With 20 passes per series, a difference of one or two passes between series is noise: a status describes a draw, not the model.
- Timing columns are opt-in (`--with-timing`) because they are only meaningful for sequential runs.

## Audit on the demo

python src/audit_prepare.py --config examples/demo/config.json --per-cell 5 --seed 42 --batch-size 8 --out audit/
# give audit/batches/*.json (never key.json) to blind reviewers, see compound/skills/blind-audit/SKILL.md or prompts/
